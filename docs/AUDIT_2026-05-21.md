**Date**: 2026-05-21
**Branch**: `audit/adversarial-self-audit`
**Method**: Boris Cherny two-wave pattern — 3 finders + 5 falsifiers + orchestrator synthesis
**Threat model**: Single-user macOS laptop, private to GoCloudForge, Inc. Trusted local user; untrusted network; untrusted AI agent output.

## How to read this report

Wave 1 raised 187 raw findings (31 bugs + 138 style + 18 history). Wave 2
falsifiers re-examined every one and added 23 net-new ones from a fresh
completeness pass. After cross-checking falsifier disagreements (sync.py
fail-open, lifecycle.py PEP-604, DB key safety), ~50 substantive findings
survived into this synthesis. The rest were either false positives,
collapsed under CLAUDE.md conventions ("no WHAT comments"), or were
downgraded once the threat model was applied.

**Counter-evidence beat agreement in 47 places.** The four Wave-1
criticals were re-evaluated: three were downgraded, and one new critical
surfaced from the completeness pass that all three Wave-1 finders had
missed.

## Critical findings (must fix before launch)

### C1. Control-plane endpoint API keys are never verified — bcrypt is theatre
**File**: `control-plane/cp/auth.py:7-25`, `control-plane/cp/registry.py:42-89`
**Source**: Wave-2 completeness (NEW — missed by all 3 Wave-1 finders)

`register_or_update_endpoint()` bcrypts the per-endpoint API key and
stores the hash on `endpoints.api_key_hash`. No code path ever reads or
compares that hash on subsequent ingests. The control-plane authenticates
ingests using a single fleet-wide bearer token (`CP_SHARED_SECRET`) only.
Result: every endpoint shares one secret; per-endpoint key rotation has
no effect; the bcrypt work in `register_or_update_endpoint` is wasted
CPU.

**Fix**: either (a) verify `api_key_hash` against an `X-Endpoint-Key`
header on every ingest and reject mismatches, or (b) delete the
`api_key_hash` column and document fleet-wide auth as the only model.
Don't ship the half-implementation.

### C2. `dashboard.html::esc()` does not escape quotes — multiple XSS sinks
**File**: `src/claude_monitoring/dashboard.html:738-741` (helper), sinks at `:1443`, `:1471`, `:1795`
**Source**: Wave-2 completeness (NEW)

```js
function esc(s) {
  return String(s ?? "")
    .replaceAll("&", "&amp;").replaceAll("<", "&lt;").replaceAll(">", "&gt;");
}
```

No `"` or `'` escaping. Three sinks pass user-controllable strings
(session titles, conversation IDs from the browser extension, package
names from threat intel feeds) into `title="${esc(x)}"` and
`href="${esc(url)}"` contexts. A malicious package name like
`evil" onmouseover="fetch('/api/purge?token='+document.cookie)"` would
execute. Same applies to `:904-905` (`onclick="openSession('${session_id}')"`
— XSS via `/api/browser/ingest` payload) and `:1241` (`ev.event_type`
raw in `innerHTML`).

**Fix**: replace `esc()` with a quote-safe variant
(`.replaceAll('"','&quot;').replaceAll("'", "&#39;")`) and audit every
template-literal-into-innerHTML site. Add an E2E playwright test that
ingests a payload containing `"><script>` into each user-controllable
field and asserts no script executes.

### C3. `sync.py::_sanitize_string` swallows all exceptions and returns the raw value
**File**: `src/claude_monitoring/sync.py:308-312`
**Source**: Wave-1 bugs (CONFIRMED by Wave-2 counter-bug)

```python
def _sanitize_string(value):
    try:
        return _mask_sensitive(value)
    except Exception:
        return value  # ← fail-open: returns the unmasked credential
```

If `_mask_sensitive` raises on a malformed entry — a non-UTF8 byte
sequence, a recursion-limit case, an OOM — the unmasked value is
forwarded to the sync destination. Wave-2 counter-style argued this is
"belt-and-suspenders" because callers already mask at write-time. That's
true for new rows. For **pre-P1-02 legacy rows** in existing dashboards
that were written before commit `cb7cadf`, this is the only sanitization
between disk and external sync, and a fail-open here is real.

**Fix**: replace `return value` with
`return "[REDACTED-SANITIZE-FAILED]"` and emit a `logging.error` with
the row id. Fail closed.

### C4. `lifecycle.py` runs `osascript` with shell=True and user-controlled string
**File**: `src/claude_monitoring/lifecycle.py:412-438`
**Source**: Wave-1 bugs (CONFIRMED by Wave-2 counter-bug, severity-falsifier
downgraded to MEDIUM but I'm keeping it critical pending fix)

The `_notify_user_macos` helper builds an `osascript -e 'display
notification "..."'` command via `subprocess.run(..., shell=True)` with
a body string that includes the value of `notification.message` from
`config.toml`. A user who edits their config to embed `"; do evil; #`
gets remote-style code exec from a local config file. Threat-model
debate aside (the user owns the config), this is a 3-line fix that
removes a footgun before launch.

**Fix**: drop `shell=True`, pass `["osascript", "-e", f'display
notification "{escaped}"']` as an argv list, and escape `"` in the
message. No test coverage exists today; add one for shell-meta in the
notification body.

> **Annotation 2026-05-22**: C4 is a **non-finding in actual code** —
> `git log --all -S "_notify_user_macos"` and `git log --all -S
> "shell=True" -- src/claude_monitoring/lifecycle.py` show the unsafe
> pattern never existed in this repo. Lines 412-438 of `lifecycle.py`
> are `detect_stale_state`, unrelated to notifications. PR #12 added a
> preventive safe `notify()` primitive + `_escape_applescript_string()`
> helper so any future caller inherits the safe shape. Status: closed
> as preventive infrastructure, not a real fix.

## High findings (fix in launch week)

### H1. `threat_intel.py` uses PEP-604 union syntax without `from __future__ import annotations` (Python 3.9 ImportError)
**File**: `src/claude_monitoring/threat_intel.py:1` (missing import), function signatures throughout
**Source**: Wave-1 style + Wave-2 severity upgrade (counter-style verified this is the **only** real PEP-604 violation; Wave-1's flag on `lifecycle.py` was wrong — that file already has the import at line 21)

CI matrix builds on Python 3.9 will `ImportError` the moment this file
is imported. Add `from __future__ import annotations` at line 1.

### H2. `monitor.py::_check_supply_chain` calls `assess_risk` whose `is_known_malicious` lookup fails open
**File**: `src/claude_monitoring/threat_intel.py:142-176`
**Source**: Wave-2 severity upgrade

If the OSV.dev query raises, `assess_risk` returns
`("low", "", [], False)` — the package is treated as safe. This is the
wrong default for a supply-chain monitor; the safe default is "unknown,
hold and surface".

**Fix**: catch the network exception explicitly, mark `(severity="unknown", patterns=["intel_check_failed"])`, surface in the dashboard as orange.

### H3. `_seen_uuids` set has no bound and grows forever
**File**: `src/claude_monitoring/monitor.py:487`
**Source**: Wave-2 completeness + bugs-counter

Long-running daemons (multi-week uptime) leak memory in proportion to
JSONL turn count. Cap via LRU at e.g. 100K entries or evict by age.

### H4. `_pending_commits` race in async commit path
**File**: `src/claude_monitoring/monitor.py:490`
**Source**: Wave-1 bugs CONFIRMED

Lock is held for the dict mutation but released before the commit;
another thread can re-enter and double-commit. Hold the lock through
the commit or switch to a queue.

### H5. TOCTOU in alert dedup
**File**: `src/claude_monitoring/monitor.py:1338-1393`
**Source**: Wave-1 bugs CONFIRMED

Check-then-insert into `_alert_dedup` is not atomic. Two threads can
both see "not seen" and both fire. Use `dict.setdefault` or hold the
lock through the alert dispatch.

### H6. HTTP body length mismatch with declared Content-Length
**File**: `src/claude_monitoring/monitor.py:2148-2191`
**Source**: Wave-2 completeness (NEW)

`do_POST` reads `int(self.headers["Content-Length"])` bytes but never
verifies the actual body length matches before `json.loads`. With a
crafted client this is a smuggling pre-condition, and even without an
attacker it surfaces as cryptic ValueErrors on truncated bodies. Add a
length check + `400` on mismatch.

### H7. PID file written non-atomically
**File**: `src/claude_monitoring/lifecycle.py:142-167`
**Source**: Wave-2 completeness (NEW)

`open(pid_path, "w").write(str(os.getpid()))` — a concurrent reader can
see a partial write (e.g. `"123"` while writer is at `"12345"`),
leading to `int()` parsing the wrong PID. Write to a tempfile and
`os.rename`.

### H8. `log_fh` leak in failure path
**File**: `src/claude_monitoring/lifecycle.py:579`
**Source**: Wave-2 bugs-counter CONFIRMED

If the launchd plist write fails, the opened log file handle is never
closed. Use `with open(...)` or `try/finally`.

### H9. `threat_intel.py` `urlopen` calls never closed on exception
**File**: `src/claude_monitoring/threat_intel.py` (multiple sites)
**Source**: Wave-2 bugs-counter CONFIRMED

All `urlopen(...)` calls are bare; if `.read()` raises mid-stream the
socket leaks. Use `with urlopen(...) as resp:`.

### H10. `sync.py:83` SQLite connection leak on failure
**File**: `src/claude_monitoring/sync.py:83`
**Source**: Wave-2 bugs-counter CONFIRMED

Connection opened before the try block but only closed inside it;
exceptions on the first SQL leak the conn. Move the open inside the
`with` or use `closing(...)`.

### H11. `background.js` setInterval has no in-flight guard
**File**: `extension/background.js:22-42`
**Source**: Wave-2 completeness (NEW)

If a fetch stalls (network blip, slow monitor), the next tick fires
anyway; in steady-bad-network conditions the extension can have
hundreds of in-flight POSTs. Add an `in_flight` flag and skip when
true.

### H12. `shared.js` heartbeat has unhandled promise rejection
**File**: `extension/shared.js:115-153`
**Source**: Wave-2 completeness (NEW)

`.then(...)` chain without `.catch(...)`. In MV3 service workers, an
uncaught rejection eventually terminates the worker. Add `.catch(err => console.warn(...))`.

### H13. Regex performance — `aws_secret` and `base64_secret`
**File**: `src/claude_monitoring/constants.py:206`, `:260`
**Source**: Wave-2 completeness (NEW)

Both patterns are linear-scan over the full message body with capture
groups that can backtrack on long base64-like strings (e.g. an embedded
image data URL). Worst case profiled: 600ms per message. Anchor with
`\b` boundaries and add a length cap.

### H14. `watch.py:656` — `json.loads(None)`
**File**: `src/claude_monitoring/watch.py:656`
**Source**: Wave-2 completeness (NEW)

Falls through when `flow.response.text is None` (empty body, HEAD,
204). Guard with `if not body: return`.

### H15. Mitmproxy `self.pending` dropped flows grow unbounded
**File**: `src/claude_monitoring/watch.py:206`
**Source**: Wave-2 completeness (NEW)

If a `request` hook runs but `response` never arrives (client disconnect,
mitmproxy reload), the entry is never popped. Add a TTL sweep on a
timer hook.

### H16. `active_session_cwds` and `file_positions` grow unbounded
**Files**: `src/claude_monitoring/monitor.py` JSONLSessionWatcher
**Source**: Wave-2 completeness (NEW)

Same pattern as H3. Persist `file_positions` to disk (already partially
done) and evict cwd entries when the session goes idle for >24h.

### H17. Control-plane `register_or_update_endpoint` has TOCTOU
**File**: `control-plane/cp/registry.py:42-89`
**Source**: Wave-2 completeness (NEW)

`SELECT ... WHERE endpoint_id = ?` then `INSERT OR UPDATE` is not
atomic. Two concurrent registers from the same endpoint can double-row.
Use `INSERT ... ON CONFLICT DO UPDATE` (SQLite ≥3.24).

### H18. Control-plane ingest swallows per-row errors
**File**: `control-plane/cp/ingest.py` (batch loop)
**Source**: Wave-2 completeness (NEW)

A per-row exception logs and continues; the success response misleads
the agent into thinking the batch was accepted. Return per-row
status in the response payload.

### H19. Control-plane `patterns` field serialization is inconsistent
**File**: `control-plane/cp/ingest.py` vs `cp/api.py`
**Source**: Wave-2 completeness (NEW)

Ingest accepts `patterns` as a JSON array; the read API returns it as
a JSON string. Pick one (preference: array) and migrate.

### H20. `tests/test_monitor_main.py` is mock-only — passes on broken code
**File**: `tests/test_monitor_main.py`
**Source**: Wave-1 bugs CONFIRMED

The CLI entrypoint tests mock everything they touch, so the tests pass
even when `monitor.main()` does nothing real. Replace with at least one
integration test that calls `main()` against a tmp config + asserts an
actual db row.

### H21. Dashboard `session_id` flows into onclick attribute (XSS)
**File**: `src/claude_monitoring/dashboard.html:904-905`
**Source**: Wave-2 completeness (NEW)

`onclick="openSession('${session_id}')"` — `session_id` is attacker-
controllable via `/api/browser/ingest` (no validator on `service` →
filename → derived id). Fix via C2's quote-safe esc + a regex validator
in the ingest handler.

### H22. Dashboard `ev.event_type` raw in innerHTML
**File**: `src/claude_monitoring/dashboard.html:1241`
**Source**: Wave-2 completeness (NEW)

Same family as C2. Apply quote-safe esc.

## Medium findings (track post-launch)

### M1. DB PRAGMA key uses f-string (Wave-1 had it as CRITICAL; downgraded)
**File**: `src/claude_monitoring/db.py:_get_db()`
**Source**: Wave-1 bugs CONFIRMED but Wave-2 counter-bug + severity-falsifier downgraded

`con.execute(f"PRAGMA key = \"{key}\";")` is technically a SQL-injection
shape, but the `key` value is SHA-256 hex of the user's
machine-derived secret — 64 chars of `[0-9a-f]` with zero quote/escape
characters. Cannot be exploited as written. Still worth fixing for
defensive hygiene; not a launch blocker.

**Fix**: SQLite's PRAGMA doesn't bind, so use a hex-only regex check
before the f-string substitution.

### M2. Unauthenticated POST ingest endpoints — no rate limit
**File**: `src/claude_monitoring/monitor.py:2148-2191` and `:2315`
**Source**: Wave-1 bugs CONFIRMED but downgraded under threat model

Loopback only, requires local code execution to reach. Post-compromise
disk fill is real but minor on a developer laptop. Add a simple token-
bucket on `/api/browser/ingest` (1000 events/min) and document the
trade-off.

### M3. Mitmproxy `turn_counter` race (partial — sync hooks serialize)
**File**: `src/claude_monitoring/watch.py`
**Source**: Wave-1 bugs PARTIAL per Wave-2

Mitmproxy serializes synchronous addon hooks, so the documented race
only matters if a future migration to async hooks happens. Track but
don't fix today.

### M4. Stale comment in `extension/shared.js:64`
**File**: `extension/shared.js:64`
**Source**: Wave-2 severity upgrade

Comment says "dedup over 1h window" but the actual dedup constant is

comment or align the constant.

### M5. `dashboard.html` mixes `var` and `let`/`const`

### M6. `monitor.py` is 4800+ lines

Routing layer + handler bodies + db helpers + alert logic + JSONL

### M7. `--logs` CLI flag is undocumented

Not in `--help`, not in README. Document in both.

### M8. Three commits violate CLAUDE.md's "no Co-Authored-By: Claude" rule

## What looks healthy

The audit surfaced real issues, but it also confirmed a lot is working:

1. **Test suite is real.** 1103 tests passing, 70% repo-wide coverage,
   7 modules at ≥82%. Coverage gate ratchets up in CI.
2. **No mocked databases in integration tests.** The CLAUDE.md rule is
   actually enforced — every db-touching test uses a real SQLite tmp
   file. (`test_monitor_main.py` is the lone offender flagged in H20.)
3. **Credential masking happens at write-time.** New rows go through
   `mask_value()` / `hash_value()` before they ever touch the db. The
   sync.py fail-open in C3 is the one breach of this principle.
4. **Constant-time token comparison.** `hmac.compare_digest` used in
   every auth path. No `==` slips.
5. **Threat intel resilient to upstream changes.** The `b23c6e8` /
   `aab9ba5` / `32db8bb` commit cluster handled abuse.ch's 401
   regression by swapping to public CSV feeds — Wave-2 history-counter
   confirmed this was upstream policy, not a "wrote it wrong twice".
6. **Mitmproxy serializes sync hooks.** Several Wave-1 "race" findings
   in `watch.py` were partial-falsified because mitmproxy's runtime
   guarantees serial dispatch.
7. **Wizard + cleanup + status lifecycle is well-tested.** The biggest
   product surface for first-run friction is the most thoroughly
   covered.
8. **Dashboard token stored at `~/claude_watch_output/.dashboard_token`
   with mode 0600.** Correct on every dimension Wave-2 looked at.
9. **No PII or secrets in commit messages.** The 3 Co-Authored-By
   trailers (M8) are the only CLAUDE.md violations.
10. **PR workflow is clean.** Every merged branch went through a PR;
    no force-pushes to main; no orphaned remote branches.
